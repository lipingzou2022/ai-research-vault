# 科研工作流规则

## 总体原则

人负责选择和判断，AI负责辅助理解、整理与执行。

```text
Zotero → ChatGPT总结 → Codex整理 → Obsidian知识网络
知识点疑惑 → ChatGPT总结 → Codex概念笔记 → Obsidian概念网络
Git项目 → Codex诊断与实验 → Obsidian证据记录
```

## 工具边界

- Zotero：论文PDF、作者、年份、DOI、Collection、原始标签和引用信息的权威来源。
- ChatGPT：论文讲解、基础知识补充、方法比较、局限分析和研究启发。
- Codex：读取元数据、整理Markdown、维护YAML、检查重复、建立确定性链接并提出待确认建议。
- Obsidian：保存长期理解、概念关系、领域地图、研究想法和实验结论。
- Git项目或服务器：保存代码、数据、环境、权重、完整日志和大型实验产物。

## 六类核心笔记

1. literature：论文笔记
2. concept：概念笔记
3. field-map：领域地图
4. idea：研究想法
5. reproduction：复现项目
6. experiment：实验记录

## 知识点讨论入口

用户与 ChatGPT 围绕可跨论文复用的知识点进行讨论后，由 ChatGPT输出普通的“知识点学习总结”，再由项目级 `$organize-concept-note` Skill整理为 `concept` 笔记。

- 用户不需要手工编写 YAML，也不需要每次重复工作流提示词。
- 总结应保留用户的原始疑惑、理解变化、误解修正、尚未理解和自我检查。
- ChatGPT解释属于 AI 辅助理解，不自动等同于论文、教材或官方资料证据。
- 已有概念必须增量更新；创建多个子概念、合并拆分或确定标准名需要用户确认。
- 一篇论文独有的方法写入 `literature`，代码实现写入 `reproduction`，具体实验写入 `experiment`，新研究假设写入 `idea`。

## 写入与更新规则

- 文献元数据以Zotero为准，Obsidian不自动反写Zotero。
- ChatGPT可以提供普通总结文本，不要求用户手工填写YAML。
- 第一次可以创建完整笔记；后续必须增量更新，不能整篇覆盖。
- Codex不得覆盖“我的判断”“我的疑问”“导师意见”“决策记录”等用户内容。
- 无法确定来源的陈述进入“待确认”，不得改写成论文事实。
- 已确认关系写入正文；推断性关系先进入“待确认关联”。
- 新建文件前必须检查Zotero item key、citation key、DOI、标题、文件名和aliases，避免重复。
- 没有经过确认的稳定citation key时，论文文件名使用Zotero item key兜底，不使用可能冲突的普通导出键。
- 不直接永久删除笔记。废弃内容优先归档；确需删除时先移入系统回收站。

## 标签与链接规则

- Zotero原始标签原样保存在 `zotero_tags`，不自动变成Obsidian标签。
- 第一版不要求使用Obsidian `tags`。
- 专业知识使用概念笔记和正文双链表达。
- 双链应放在能够说明关系的句子中，避免只堆“相关笔记”列表。
- 同一个概念只保留一个主节点，中文、英文全称和缩写写入 `aliases`。

## 人工确认边界

Codex可以直接处理格式、路径、客观元数据和确定性链接；以下事项必须由用户确认：

- 支持、反驳、优于、继承等科研关系；
- 概念合并、拆分和标准命名；
- 领域地图主干调整；
- 研究想法升级、采用、暂停或否定；
- 实验是否支持假设；
- 大批量移动、重命名、归档或删除。

## 第一版实施范围

先用真实论文验证：

```text
Zotero文献
→ ChatGPT总结
→ Codex生成论文笔记
→ 已有概念链接
→ 待确认概念与领域地图更新
```

模板和自动化必须根据试运行结果迭代，不提前追求完整。
