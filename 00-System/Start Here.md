# 科研知识库入口

这份文件是新任务恢复项目上下文的入口。长期规则保存在文件中，不依赖某一次聊天记录。

## 系统目标

建立一套长期可维护的半自动科研工作流：

```text
人触发 → AI辅助执行 → 人进行判断

Zotero论文
→ ChatGPT导师式讨论
→ Research Note总结文本
→ Codex结构化整理
→ Obsidian知识网络

论文代码
→ Codex项目诊断
→ Context Packet
→ ChatGPT高级推理
→ Codex复现、修改和实验
→ Obsidian证据回流
```

## 核心规则入口

- [[Research Workflow]]：工具边界、人工确认边界和写入规则
- [[YAML Dictionary]]：六类笔记的固定字段与状态值
- [[Naming Rules]]：文件名、稳定编号和重命名规则
- [[Templates/Literature Note|Literature Note 模板]]：论文笔记模板

## 六类知识对象

| 目录 | 笔记类型 | 主要作用 |
|---|---|---|
| `01-Literature` | literature | 保存论文理解、证据、局限和个人判断 |
| `02-Concepts` | concept | 保存可跨论文复用的概念理解 |
| `03-Field-Maps` | field-map | 组织领域结构、论文位置和研究空白 |
| `04-Ideas` | idea | 保存想法来源、证据、成熟度与验证状态 |
| `05-Reproduction` | reproduction | 连接论文、代码仓库、环境与复现进度 |
| `06-Experiments` | experiment | 保存假设、版本、变量、结果和结论 |

## 新论文的标准入口

用户提供：

1. 论文标题或 Zotero item key；
2. ChatGPT 深度讨论后形成的 Research Note；
3. 阅读级别或本次处理目标。

Codex执行：

1. 读取本文件和三份核心规则；
2. 从 Zotero核对元数据与原始标签；
3. 检查论文和概念是否已经存在；
4. 创建或增量更新论文笔记；
5. 建立确定性链接；
6. 汇总需要用户确认的语义链接、概念变更和地图调整；
7. 用户检查后更新 `note_status`。

## 新任务使用方式

- 必须从“AI科研知识库”本地项目中创建 Codex 任务。
- 一个任务尽量只对应一个明确成果，例如“一篇论文入库”“一次概念整理”或“一个复现项目诊断”。
- 不必复制以前的全部聊天；先让 Codex读取本文件和相关笔记。
- ChatGPT讨论可以留在相应的 ChatGPT 项目中，最终只需把 Research Note总结文本交给 Codex。

## 当前里程碑

下一阶段不是立即追求全自动化，而是：

1. 继续处理3至5篇真实论文；
2. 检查字段、概念、双链和领域地图是否稳定；
3. 处理标签膨胀与重复概念；
4. 再创建 `literature-note-generator` Skill；
5. 随后接入复现项目和实验结果回流。

## 维护节奏

- 每篇论文完成后：用户检查论文笔记和待确认关联。
- 每处理5篇论文：进行一次概念去重、断链检查和领域地图复查。
- 每月：检查活跃想法、复现项目和实验状态。
- 每学期：归档长期无效内容并检查知识库备份。
