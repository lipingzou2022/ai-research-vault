# 整理概念笔记

把 ChatGPT 知识点讨论转化为可长期维护的 `concept` 笔记。接受简短自然语言触发，不要求用户重复粘贴工作流说明。

## 输入

通常只需要：

- 知识点名称；能从总结中明确推断时可以省略；
- ChatGPT 根据讨论生成的总结文本；
- 用户可选提供的论文、教材、课程或官方资料来源。

如果总结足以确定主概念，直接处理。只有当多个候选主概念会导致明显不同的文件结构时才询问用户。

## 开始前

读取：

1. 项目根目录 `AGENTS.md`；
2. `00-System/Start Here.md`；
3. `00-System/Research Workflow.md`；
4. `00-System/YAML Dictionary.md`；
5. `00-System/Naming Rules.md`；
6. `00-System/Templates/Concept Note.md`；
7. 候选已有概念笔记及相关领域地图。

## 路由边界

- 可跨论文复用的原理、方法、模型、模块、任务、数据集、指标或问题：写入 `02-Concepts`。
- 某篇论文独有的方法与结论：写入或建议写入 `01-Literature`。
- 某个代码仓库的实现细节：写入或建议写入 `05-Reproduction`。
- 一次具体实验的配置与结果：写入或建议写入 `06-Experiments`。
- 用户提出的新方案或研究假设：写入或建议写入 `04-Ideas`。

不要把一段讨论机械地全部塞进概念笔记。允许保留与主概念直接相关的内容，其他类型内容先报告分流建议。

## 查重与命名

在创建文件前搜索 `02-Concepts` 中的：

- 文件名和标题；
- 中文名、英文全称、缩写和 `aliases`；
- 已有双链与明显同义表达。

已有主节点时增量更新，不创建重复笔记。概念标准名、合并、拆分或大范围重命名需要用户确认；常用同义名称写入 `aliases`。

## 新建与更新

新概念默认使用：

```yaml
type: concept
note_status: draft
maturity: seed
```

只添加实际有用的可选字段。新建时使用概念模板；更新时保留原结构和人工内容，按语义合并，避免重复段落。

必须保留或整理：

- 用户最初的疑惑及产生疑惑的原因；
- 当前形成的理解和思维模型；
- 输入、输出、核心流程和各部分存在的原因；
- 被纠正的误解与容易混淆的概念；
- 尚未解决的问题和自我检查题；
- 有日期的学习记录。

不得覆盖“我的原始疑惑”“我的当前理解”“我的判断”等人工内容。后续讨论应增量合并，并在“学习记录”中追加日期与理解变化。

## 来源与证据

- ChatGPT解释属于 AI 辅助形成的当前理解，不自动视为论文证据。
- 用户提供或知识库已有的论文、教材、课程和官方资料应明确列入“已验证来源”。
- 没有可靠来源的解释写入“AI辅助解释／待验证”，不得虚构文献。
- 如果讨论引用了可识别论文，可按需核对 Zotero；不要为普通概念讨论强制调用 Zotero。
- `note_status` 可在用户检查后改为 `reviewed`；`maturity` 升级必须由用户确认。

## 双链

- 指向已存在概念、论文和领域地图的确定性链接可以直接建立。
- 双链放入能够说明关系的句子，不堆砌无语义列表。
- 新建多个子概念、概念合并拆分，以及“优于、导致、支持、反驳、继承、适用于”等较强语义关系，先形成建议并等待用户确认。

## 完成报告

说明：

1. 新建或更新了哪个概念笔记；
2. 保留了哪些用户疑惑和理解变化；
3. 建立了哪些确定性链接；
4. 哪些内容仍待验证；
5. 哪些拆分、命名或语义关系需要用户确认；
6. 用户检查后是否应将 `note_status` 改为 `reviewed`。

除非用户同时明确要求，不自动提交或推送 Git 备份。
