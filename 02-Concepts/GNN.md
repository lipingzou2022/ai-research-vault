# GNN

> [!summary] 一句话理解
> GNN（Graph Neural Network，图神经网络）面向“对象 + 对象之间的不规则关系”，让每个节点从图中与其相连的节点聚合信息，形成新的节点或整图表征。

## 我的原始疑惑

- “传感器之间的关系”具体是什么？
- GNN 中的邻居是不是物理位置上挨着的传感器？
- 传感器图中的边由谁决定，怎样判断它是合理的？

## 我的当前理解

GNN 的基本输入不是规则时间轴或二维网格，而是一组节点、节点特征以及节点之间的边。对于电子鼻，可以把每个传感器视为节点，把传感器自身的数据作为节点特征，再用边表达某种可说明的关联。

GNN 中的“邻居”由图的边决定，不等于物理距离近。两个传感器即使在设备中相距较远，只要有足够依据把它们连接起来，仍可互为图邻居；反过来，物理相邻也不自动证明应当连边。

## 为什么需要它

- 表达数量可变或连接不规则的对象关系；
- 让节点结合自身信息与关联节点信息更新表征；
- 获得单个节点的输出，或聚合为整个图的输出；
- 将“关系结构”本身纳入模型，而不是仅把所有变量平铺成向量。

## 输入与输出

- 节点 `Node`：研究中的对象，例如各个气体传感器。
- 节点特征：每个节点携带的数据，例如响应值、统计特征或时序编码。
- 边 `Edge`：对象之间被定义或学习到的关系。
- 可选边特征：关系的类型、强度或其他属性。
- 输出：更新后的节点表征、边表征或整图表征，进一步用于分类或回归。

```text
节点特征 + 图的边
→ 邻居消息
→ 聚合
→ 更新节点表征
→ 节点任务 / 整图任务
```

## 核心流程与组成

消息传递可以先用下面的直觉理解：

```text
当前节点自己的信息
+ 与它相连节点的信息
→ 聚合
→ 形成新的节点表示
```

关键不只在聚合函数，也在图如何构建。边可以来自已知物理机制、传感材料属性、响应相关性、实验设计或模型学习，但不同构图方式会引入不同假设。构图依据和是否使用了测试信息都必须记录。

## 在电子鼻中的位置

在[[电子鼻表征学习网络选择]]中，GNN 对应“传感器及其不规则关系网络”这一建模视角。节点可表示[[气体传感器阵列]]中的传感器，节点特征来自[[电子鼻信号处理]]后的数据，整图表征再进入[[电子鼻模式识别]]。

目前这只是合理的问题表达，不是已经由现有笔记证明的性能结论。真实研究必须回答：边代表什么、为什么这样连、图是否随样本变化、构图是否产生数据泄漏，以及 GNN 是否比不使用图结构的基线更有效。

## 容易混淆的概念

- **GNN 邻居与物理邻居**：图邻居由边定义，物理距离只是可能的构图依据之一。
- **GNN 与 [[CNN]]**：CNN 通常在规则局部网格或序列上共享卷积；GNN 在不规则连接关系上传递与聚合消息。
- **节点特征与边**：节点特征描述对象自身，边描述对象之间的关系。
- **相关性与因果关系**：响应相关可以用于候选构图，但不能自动解释为物理或因果联系。

## 本次纠正的错误理解

1. **图中的邻居就是空间上靠得近。** → 错误。邻居由边定义。
2. **有多个传感器就应该使用 GNN。** → 错误。必须先证明关系结构值得显式建模。
3. **构图只是实现细节。** → 不准确。边的定义包含核心研究假设，可能直接影响结论。

## 与其他概念的关系

若数据关系主要是规则时间局部模式，可比较 [[CNN]]；若只是固定特征的整体组合，可使用 [[MLP]] 作为基线；若节点特征本身是长序列，可以先由[[序列建模基础]]或 [[Transformer]] 产生节点表示，再讨论是否需要图结构，但这种融合方案需在具体论文中单独分析。
