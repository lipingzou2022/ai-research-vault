# SNN

> [!summary] 一句话理解
> SNN（Spiking Neural Network，脉冲神经网络）用脉冲是否发生及其时间来传递信息，适合进一步研究事件驱动、脉冲时序、长期在线与神经形态硬件约束下的计算。

## 我的原始疑惑

- 什么叫事件驱动和脉冲时序？
- 连续传感器信号怎样进入 SNN？
- 为什么 SNN 可能低功耗？普通 GPU 上运行也会省电吗？
- 什么是神经形态硬件，什么情况下才真正需要 SNN？

## 我的当前理解

SNN 的选择理由不应简化为“输入是时间序列”。普通连续信号可以先经过 Spike Encoding（脉冲编码），将信息转为脉冲是否出现、出现时间或脉冲密度；SNN 再通过神经元内部状态和阈值放电处理这些事件。

事件驱动意味着没有相关事件时可以减少部分计算，发生脉冲时再更新或传递信息。但 SNN 不会自动带来低功耗：实际收益依赖脉冲是否足够稀疏、算法实现以及硬件能否真正按事件执行。普通 GPU 上模拟脉冲网络不保证更加省电。

## 为什么需要它

- 直接利用事件发生时间或脉冲密度表达信息；
- 面向持续在线、实时响应或稀疏事件场景；
- 探索与神经形态硬件相匹配的事件驱动计算；
- 在能耗是明确评价目标时，提供区别于常规人工神经网络的计算范式。

## 输入与输出

- 原始输入：连续传感器信号，或事件传感器直接产生的事件。
- 编码后输入：Spike Train（脉冲序列）。
- 内部状态：神经元随时间积累的状态，以及达到阈值后的放电事件。
- 输出：脉冲计数、脉冲时间或由其解码得到的类别、检测结果等。

```text
连续电子鼻响应
→ 脉冲编码
→ Spike Train
→ SNN
→ 脉冲时序表征
→ 分类 / 检测
```

## 核心流程与组成

```text
输入脉冲到达
→ 神经元状态随时间变化
→ 达到阈值
→ 发出脉冲
→ 状态更新或重置
```

脉冲“有没有、何时出现、出现多密集”都可能承载信息。Spike Encoding 决定连续数据如何被转换，神经元模型决定状态如何积累和放电，训练方法决定网络怎样学习；三者都可能影响性能与能耗。

## 在电子鼻中的位置

[[电子鼻表征学习网络选择]]把 SNN 放在事件驱动、脉冲时序、低功耗和长期在线需求下考虑。输入来自[[气体传感器阵列]]与[[电子鼻信号处理]]，任务输出进入[[电子鼻模式识别]]。

[[ZOTERO-QB28SJ6R - 电子鼻技术及其应用研究进展]]将 SNN 列入电子鼻模式识别方法范围，但当前笔记没有足够原始研究证据证明其在特定电子鼻任务上的能耗或精度优势。

## 容易混淆的概念

- **时间序列与 SNN**：时间序列也可由 [[CNN]]、RNN/LSTM 或 [[Transformer]] 处理；SNN 额外强调脉冲事件和执行方式。
- **事件驱动与实时**：能快速响应不等于实现一定按事件稀疏计算。
- **SNN 与低功耗**：低功耗是待测结果，不是由网络名称自动保证的属性。
- **脉冲编码与神经元放电**：前者把外部数据转换成脉冲，后者描述网络内部状态达到阈值后产生脉冲。

## 本次纠正的错误理解

1. **只要是时间序列，就应该考虑 SNN。** → 错误。还要有事件、时序编码、在线或能耗等具体动机。
2. **SNN 天生低功耗。** → 错误。低功耗依赖稀疏事件、实现方式和硬件支持。
3. **在普通 GPU 上运行 SNN 一定更省电。** → 错误。GPU 模拟可能无法获得神经形态硬件的事件驱动优势。
4. **脉冲只有 0 和 1，所以信息更少。** → 不完整。脉冲时间、频率和群体活动也可携带信息。

## 与其他概念的关系

若目标只是提取连续信号的局部模式，可比较 [[CNN]]；若重点是常规长程序列依赖，可参考[[序列建模基础]]与 [[Transformer]]。SNN 的核心区别在于信息表示、神经元动态和可能的事件驱动执行，而不是简单替代所有时序模型。
