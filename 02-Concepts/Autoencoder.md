# Autoencoder

> [!summary] 一句话理解
> Autoencoder（自编码器）用“输入经过 Encoder 压缩为表征，再由 Decoder 尝试重构输入”的训练框架，迫使模型学习能够保留重要信息的内部表示。

## 我的原始疑惑

- Encoder、Autoencoder 和 Transformer 是不是同一层级的概念？
- Decoder 为什么要重构输入；最终分类时还要不要它？
- 中间表征 `z` 在测试阶段究竟有什么用？
- 自编码器能否让漂移前后的同类气体在表征空间中靠近？
- 多网络联合与多任务学习分别改变了什么？

## 我的当前理解

### Encoder、Representation 与 Autoencoder

Encoder（编码器）是一种**功能角色**：把原始输入 `x` 转换为内部表征 `z`。[[CNN]]、[[序列建模基础|LSTM]]、[[Transformer]] 或其他网络结构都可以承担这个角色。

Representation（表征）`z` 是模型从输入中形成的内部表示。下游分类器、回归器或生成模块通常不再直接使用原始 `x`，而是读取 `z` 或由它继续加工得到的表示。

Autoencoder 是一种表示学习框架：

```text
x
→ Encoder
→ z
→ Decoder
→ x_hat
```

通过让重构结果 `x_hat` 尽量接近 `x`，重构损失把训练信号传回 Decoder 和 Encoder，使 `z` 保留足以支持重构的信息。

### Transformer 与 Autoencoder 不在同一层级

```text
Transformer
→ 网络结构
→ 决定如何处理序列和建立位置间关系

Autoencoder
→ 训练与表示学习框架
→ 用重构目标约束 Encoder 学习表征
```

二者可以组合：

```text
x
→ Transformer Encoder
→ z
→ Decoder
→ x_hat
```

这里“Transformer Encoder”描述 Encoder 的具体结构；“Autoencoder”描述 Encoder 与 Decoder 如何围绕重构目标组织训练。

## 为什么需要它

Autoencoder 比较自然的候选场景包括：

1. 无标签数据较多，希望先利用重构任务学习表示；
2. 原始数据高维复杂，希望获得更紧凑的潜在表示；
3. 需要去噪、异常检测或缺失信息恢复；
4. 需要从潜在表示恢复或生成原始对象，例如某些 CAD 序列表示任务。

如果已有大量可靠标签且目标只是分类，自编码器不一定带来额外收益。是否使用它应通过与直接监督训练等基线的公平实验判断。

## 输入与输出

- Encoder 输入：原始数据 `x`。
- Encoder 输出：潜在表征 `z`。
- Decoder 输入：`z`。
- Decoder 输出：重构结果 `x_hat`。
- 训练目标：最小化 `x_hat` 与 `x` 之间的 Reconstruction Loss（重构损失）。

训练完成后，若最终任务只是分类，可以只保留 Encoder 和任务头：

```text
x_test
→ 训练好的 Encoder
→ z_test
→ 分类头
→ 类别
```

但这不是所有自编码器应用的固定做法。在去噪、异常检测、恢复或生成任务中，Decoder 和重构结果本身仍可能是最终需要的部分。

## 核心流程与组成

### Encoder

负责把输入映射到潜在空间。它需要尽量保留当前训练目标所要求的信息，但 `z` 的含义不是天然确定的，取决于网络结构、瓶颈、损失函数和数据。

### Latent Representation

`z` 是潜在表征。理想的分类表征可能让同类样本更接近、异类样本更可分，但**标准重构损失本身并不保证这一点**：模型也可能保留与重构有关、却不利于分类或漂移鲁棒性的细节。

### Decoder

负责从 `z` 生成 `x_hat`。在表示学习语境中，它提供一场“重构考试”：

```text
重构误差较大
→ Reconstruction Loss 增大
→ 反向传播
→ 更新 Decoder 和 Encoder
→ 调整 z 所保留的信息
```

### Reconstruction Loss

衡量重构结果与目标之间的差异。具体损失必须与数据形式相匹配；“数值上重构得好”也不自动等于“对最终科研任务有用”。

## `z` 与电子鼻传感器漂移

[[传感器漂移]]会使同一种气体在不同时间产生不同的原始响应。表征层面的理想目标可以写成：

```text
漂移前同类样本 x_old → Encoder → z_old
漂移后同类样本 x_new → Encoder → z_new

希望：z_old 与 z_new 在任务相关信息上保持接近
```

这表达的是“原始信号可以变化，但任务相关的气味表示尽量稳定”。不过，普通 Autoencoder 只要求重构输入，可能把漂移因素也忠实编码进 `z`。若要学习漂移不变表示，通常还需要分类监督、分布对齐、对比约束或其他明确目标；具体方法和有效性必须由原始研究与实验验证。

## 多任务学习怎样约束表征

同一个 Encoder 得到 `z` 后，可以连接多个任务头或训练目标：

```text
                    ┌→ 分类：保留类别判别信息
x → Encoder → z ────┼→ 重构：保留输入信息
                    ├→ 分布对齐：减小域或时间差异
                    └→ 浓度回归：保留连续浓度信息
```

总训练目标可以抽象为多个 Loss 的加权组合：

```text
Total Loss
= 分类损失
+ λ_recon × 重构损失
+ λ_align × 对齐损失
+ λ_reg × 回归损失
```

多个任务从不同角度约束同一个 `z`，但不保证一定互相帮助。任务之间可能冲突，损失权重、标签质量和评价协议都会影响最终结果。

## 多网络联合与多任务学习

| 概念 | 主要改变什么 | 示例 |
| --- | --- | --- |
| 多网络联合 | Encoder 怎样处理输入、提取表征 | CNN + LSTM、CNN + Transformer |
| 多任务学习 | 用哪些目标训练共享表征 | 分类 + 重构 + 分布对齐 + 回归 |

二者可以同时存在：

```text
x
→ CNN + Transformer 组成的 Encoder
→ z
→ 分类 / 重构 / 对齐等多个训练目标
```

网络组合并不自动等于多任务学习；多个 Loss 也不要求 Encoder 一定由多个网络组成。

## 容易混淆的概念

- **Encoder 与 Autoencoder**：Encoder 是 `x → z` 的功能角色；Autoencoder 是包含 Encoder、Decoder 与重构目标的框架。
- **Encoder 与 Transformer Encoder**：前者是通用角色；后者是用 Transformer 编码结构实现该角色。
- **Autoencoder 与 Encoder-Decoder**：并非所有 Encoder-Decoder 都是自编码器。翻译模型的输出是目标语言，标准自编码器则重构输入或其干净版本。
- **重构表征与判别表征**：能重构输入的 `z` 不一定最适合分类。
- **多网络联合与多任务学习**：前者主要改模型结构，后者主要改训练目标。
- **训练目标与测试路径**：训练时用于约束表示的 Decoder 或辅助任务头，部署时不一定保留。

## 本次纠正的错误理解

1. **Autoencoder 和 Transformer 是二选一的同类网络。** → 不准确。一个主要描述训练框架，一个描述可用于实现 Encoder 的网络结构，二者可以组合。
2. **Decoder 是测试模型是否学会的模块。** → 不准确。Decoder 是训练与推理结构的一部分，其作用取决于任务，不等于测试集。
3. **`z` 只是临时变量，最终没有用途。** → 错误。下游任务通常正是使用 `z` 或其进一步变换。
4. **重构得好就一定能把同类样本聚在一起。** → 不保证。重构目标与分类、漂移不变目标并不完全相同。
5. **加入的任务越多，表示一定越好。** → 不保证。任务可能冲突，权重和实验设计需要验证。
6. **Autoencoder 的价值永远不在重构结果。** → 过于绝对。在表示学习中常关注 `z`；在去噪、恢复、异常检测或生成任务中，重构本身也可能是目标。

## 与其他概念和研究任务的关系

- [[Transformer]]、[[CNN]]或 LSTM 可以承担 Encoder 的具体结构角色。
- [[电子鼻信号处理]]中出现的降噪自编码器，是把重构框架用于信号改善的一种方向。
- 面对[[传感器漂移]]时，可以把“学习任务相关且跨时间稳定的 `z`”作为候选目标，但需要额外约束和实验验证。
- 在[[AI for CAD 领域地图]]的生成与重建任务中，Encoder 可压缩 CAD 表示，Decoder 可尝试恢复或生成对象；具体结论须绑定真实论文。
