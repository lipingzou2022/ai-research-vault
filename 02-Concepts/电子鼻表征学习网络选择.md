# 电子鼻表征学习网络选择：MLP、CNN、RNN/LSTM、Transformer、GNN、SNN

> [!summary] 一句话理解
> 网络选择不应从“哪个模型最强”开始，而应从“一个电子鼻样本长什么样、其中哪种关系最关键”开始：固定特征组合、局部时序、长程依赖、关系图或事件脉冲，分别自然导向不同的单一网络。

## 本次学习定位

本笔记不是重写各网络的完整数学细节，而是保存一套可复用的选择框架。已有 [[序列建模基础]] 承载 FNN、RNN/LSTM 的通用机制，[[Transformer]] 承载 Attention、位置编码和 Encoder/Decoder 的深入理解；本页新增电子鼻语境下“数据关系 → 网络结构”的判断入口。

```text
先看样本长什么样
→ 找最重要的数据关系
→ 选择结构上最自然的单一网络
→ 再决定是否需要后续的融合、比较或改造
```

## 我的原始疑惑

- 为什么不同数据结构要选择不同网络，为什么不能把所有输入都交给 MLP？
- 电子鼻为何有时人工提取峰值、RMS 等特征，有时又直接使用原始信号？“表征”是什么？
- 8 个传感器为什么仍可使用 1D CNN；Channel、卷积维度和物理空间关系如何区分？
- CNN 能处理时间序列时，为什么仍需要 RNN/LSTM 或 Transformer？
- GNN 的邻居是否就是物理位置相邻的传感器？
- SNN 中事件驱动、脉冲时序、低功耗和神经形态硬件各是什么意思，何时才真正需要它？

## 我的当前理解：从数据关系选网络

| 最重要的数据关系 | 优先想到的单一网络 | 当前直觉 |
| --- | --- | --- |
| 已准备好的固定长度特征之间的组合 | [[MLP]] | 学变量的非线性组合 |
| 连续时间附近的小片段共同有意义 | [[CNN\|1D CNN]] | 学局部上升、峰值、短时振荡等模式 |
| 当前状态依赖此前发生过程 | RNN / LSTM | 通过状态顺序传递历史 |
| 远距离位置之间需要直接交互 | [[Transformer]] | 直接寻找全局相关位置 |
| 对象及其不规则关系网络 | [[GNN]] | 节点从图中关联节点聚合信息 |
| 脉冲时序、长期在线、事件驱动或低功耗 | [[SNN]] | 用事件发生的时间与密度表达信息 |

这不是“模型推荐排行榜”，更不是任何任务的唯一答案。它只帮助先提出合理候选：网络结构应该优先匹配数据中需要被保留和利用的关系。

## [[MLP]]：固定特征向量的组合关系

若每次实验已经从传感器响应中得到峰值、响应时间、恢复时间、RMS、频域能量等固定长度特征，例如 8 个传感器各取 5 个特征形成 40 维向量，MLP 是自然起点：

```text
[f1, f2, …, f40]
→ MLP
→ 学习非线性组合
→ 气体类别 / 连续浓度
```

MLP 不是“完全不能学时间关系”，而是其结构没有优先强调相邻时间点应共同处理。把很长原始序列直接展平输入，模型可以学习关系，但会丢失“哪些数字彼此相邻”这一结构归纳偏置。

## [[CNN]]：局部时序与通道

CNN 的核心条件不是数据表有几行几列，而是“附近的一小段数据共同形成有意义模式”。对时间曲线 `0.2 → 0.5 → 0.9`，连续点合起来可表示快速上升；1D 卷积核沿时间轴滑动，适合提取局部峰值、上升 / 恢复片段或短时振荡。

有 8 个传感器时，可将它们理解为 8 路同时采集的输入通道。示意输入形状可为 `B × C × T`：

```text
B：batch
C：传感器通道，例如 8
T：时间点，例如 1000
```

1D / 2D 取决于卷积沿多少个**有意义的关系维度**滑动，不取决于传感器数量。若传感器仅因 PCB 布线相邻，并无气体扩散或空间语义，不能仅凭 `S1 S2 / S3 S4` 的排版就使用 2D CNN。只有空间位置本身携带可解释关系时，二维建模才更自然。

## RNN/LSTM 与 Transformer：局部、顺序与全局

CNN 擅长局部窗口，但电子鼻的“基线 → 气体进入 → 响应 → 稳定 → 恢复”过程还可能依赖较长历史。[[序列建模基础]] 中的 RNN 会逐时间步处理序列，并以 Hidden State 压缩此前信息；LSTM 用门控机制更有能力管理长期记忆。

```text
CNN：附近发生了什么？
RNN / LSTM：此前过程怎样影响当前？
Transformer：全局哪些位置与当前位置直接相关？
```

Transformer 允许当前位置直接关注远处位置，不必让信息完全经过多个时间步传递；注意力本身却不天然理解先后顺序，因此仍需要位置编码。其具体 Attention、FFN、残差与位置编码机制保留在 [[Transformer]]，本页不重复展开。

## [[GNN]]：关系定义的邻居

GNN 处理的是“对象 + 对象之间的关系”，而非规则时间轴或二维网格。对于传感器，节点可以是传感器本身，节点特征可以是各自的响应数据，边则表达经人定义或学习到的关联。消息传递使节点从关联节点收集信息，形成新的节点或整图表征。

关键纠正：GNN 的邻居是**图中通过边定义的关联对象**，不必等于物理位置相邻。两个传感器即使相距较远，只要响应相关性、材料相似性或已知物理关系支持连接，也可成为图邻居；边的定义本身需要明确证据与研究设计。

## [[SNN]]：事件与硬件约束

SNN 的选择逻辑不只是“数据是时间序列”。更强的动机通常是长期在线、低功耗、事件驱动、脉冲时序或神经形态硬件约束。

```text
连续传感器信号
→ Spike Encoding
→ Spike Train
→ SNN
→ 脉冲时序表征
→ 分类 / 检测
```

事件驱动意味着没有明显事件时可少计算、发生事件时重点处理。脉冲是否出现、何时出现、出现多密集都可携带信息。低功耗不是 SNN 的自动属性：通常需要稀疏事件和支持事件驱动的神经形态硬件共同实现；在普通 GPU 上运行 SNN 未必更省电。

## 原始信号、人工特征与表征学习

“表征”可以暂时理解为：把原始数据变成模型可用于完成任务的形式。电子鼻可走不同路线：

```text
原始响应
→ 人工特征（峰值、RMS、响应时间等）
→ 固定特征向量
→ MLP 或传统模型

原始或轻度预处理时序
→ CNN / RNN-LSTM / Transformer 等
→ 模型自动学习中间表征
→ 任务输出
```

端到端不等于“完全不预处理”。去噪、基线校正、归一化、长度对齐等仍可能必要；区别是判别性特征主要由人预先规定，还是由模型围绕最终任务学习。

## 输入与输出示意

以下 shape 只用于理解，并非某篇论文的固定实现。

| 网络 | 常见示意输入 | 中间表征 / 输出 |
| --- | --- | --- |
| MLP | `B × F` | 固定向量表征 → 分类 / 回归 |
| 1D CNN | `B × C × T` | 局部时序表征 → 分类 / 回归 |
| RNN/LSTM | `B × T × C` | 隐藏状态 / 时序表征 → 分类 / 回归 |
| Transformer | `B × T × C` 加位置表示 | 全局时序表征 → 分类 / 回归 |
| GNN | 节点特征 + 边 | 节点 / 整图表征 → 分类 / 回归 |
| SNN | Spike Train | 脉冲时序表征 → 分类 / 检测 |

## 容易混淆与本次纠正

1. **多个传感器就等于二维数据。** → 传感器数量不等于二维空间关系；卷积维度取决于有意义的邻接结构。
2. **CNN 自动知道全部长期关系。** → CNN 结构天然更偏局部模式；长程关系应具体分析。
3. **LSTM 与 Transformer 都是时间网络，所以差不多。** → LSTM 依赖顺序状态传递，Transformer 直接建立位置间全局交互。
4. **GNN 的邻居就是空间距离近。** → 邻居由图的边定义。
5. **时间序列就该使用 SNN。** → SNN 更强调事件、脉冲时序和软硬件功耗约束。
6. **SNN 一定低功耗。** → 低功耗依赖稀疏事件与执行硬件，不能预设。
7. **原始数据输入就是完全不预处理。** → 端到端模型仍可能需要合理预处理。

## 与电子鼻研究的关系

[[电子鼻信号处理]] 决定可获得原始时序、人工特征还是其他表示；[[电子鼻模式识别]] 再将这些表示映射为类别、浓度或状态。本页帮助在二者之间提出网络候选，但不直接断言某网络必然优于另一网络。

真实论文比较时，应额外检查：数据量、训练 / 测试划分、传感器漂移、预处理、模型参数量、调参预算、评价指标和功耗测量条件。没有这些对照，不能把网络名称当作性能证据。
